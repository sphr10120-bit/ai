# ربات خلاصه‌ساز اخبار بازی برای Railway

این سرویس با نشست حساب تلگرام، کانال‌های عمومی `myzoomg`، `gamefa_official`، `vigiatonet` و `NexusGamesIR` را پایش می‌کند. با مدل `gpt-6-luna` در Coarena، هر پست را ابتدا از نظر خبری‌بودن ارزیابی می‌کند و فقط خبر واقعی دربارهٔ بازی‌های ویدیویی را به فارسی خلاصه کرده و فوراً در `@pixelmediair` منتشر می‌کند. تبلیغ، محتوای اسپانسری، قرعه‌کشی، مسابقه، نظرسنجی، تخفیف صرف، راهنما، ترفند، نظر شخصی، میم و محتوای مبهم/غیرخبری منتشر نمی‌شود. این پروژه فقط پست‌های متنی و کپشن را پردازش می‌کند؛ پست رسانه‌ایِ بدون متن نادیده گرفته می‌شود.

## قالب انتشار

- تیتر برجسته با پیشوند `🟦`، حداکثر دو خط.
- دو بند عادی، هرکدام حداکثر سه خط.
- یک خط فاصله و سپس `🆔 @pixelmediair` به‌صورت برجسته.
- لینک پست منبع به خروجی اضافه نمی‌شود.

## آماده‌سازی نشست تلگرام

1. در `my.telegram.org` برای حساب تلگرامت `api_id` و `api_hash` بگیر.
2. پایتون و وابستگی‌ها را روی رایانهٔ خودت نصب کن: `python -m pip install -r requirements.txt`.
3. در محیط محلی متغیرهای `TELEGRAM_API_ID` و `TELEGRAM_API_HASH` را تنظیم کن و `python create_session.py` را اجرا کن.
4. کد ورود تلگرام را در همان ترمینال محلی وارد کن. اسکریپت مقدار `TELEGRAM_SESSION` را چاپ می‌کند. این رشته دسترسی کامل نشست حساب است؛ آن را در چت، مخزن عمومی یا کد قرار نده.
5. در تنظیمات Railway، مقدار نشست را به‌عنوان متغیر محرمانهٔ `TELEGRAM_SESSION` اضافه کن.

از حسابی استفاده کن که مجاز است در کانال‌های منبع محتوا را بخواند و در مقصد پیام منتشر کند. نشست تولیدشده در Railway را در هیچ جای دیگری منتشر نکن. اگر افشا شد، نشست را از تنظیمات حساب تلگرام لغو کن و نشست تازه بساز.

## Coarena

یک کلید شخصی Coarena با scope `inference:write` بساز، شرایط Model API را بپذیر و کلید را در Railway به‌عنوان `COARENA_API_KEY` تنظیم کن. آدرس API در کد `https://coarena.ai/api/v1` است و شناسهٔ مدل دقیقاً `gpt-6-luna` می‌ماند. اگر این مدل در دسترس نباشد، سرویس خطا را ثبت می‌کند و مدل دیگری را خودکار انتخاب نمی‌کند.

توجه: طبق مستندات Coarena، درخواست و پاسخ API ذخیره می‌شوند و ممکن است در مجموعه‌داده‌هایی که سرویس مجوز می‌دهد استفاده شوند.

## استقرار Railway

1. این پوشه را به یک مخزن خصوصی GitHub منتقل و در Railway به‌عنوان پروژه از GitHub وصل کن.
2. در Railway یک سرویس Worker بساز. دستور اجرا از `Procfile` خوانده می‌شود: `python main.py`.
3. در بخش Variables، این متغیرها را اضافه کن: `TELEGRAM_API_ID`، `TELEGRAM_API_HASH`، `TELEGRAM_SESSION`، `COARENA_API_KEY` و `SOURCE_CHANNELS`.
4. مقدار پیش‌فرض `SOURCE_CHANNELS` همان چهار کانال اعلام‌شده است. می‌توانی نام‌های کاربری عمومی یا لینک‌های `t.me` را با کاما جدا کنی.
5. مقصد پیش‌فرض `@pixelmediair` است. اگر آن را تغییر دادی، `DESTINATION_CHANNEL` را تنظیم کن.

برای جلوگیری از ارسال تکراری، شناسهٔ پیام‌های موفق در SQLite نگهداری می‌شود. روی Railway باید یک Volume را به مسیر پروژه متصل کنی تا فایل `data/processed.sqlite3` بین restartها پایدار بماند؛ مقدار `DATABASE_PATH` را می‌توانی روی مسیر Volume تنظیم کنی. اگر Volume فعال نباشد، بعد از restart سابقهٔ ارسال از بین می‌رود و احتمال بازنشر پیام‌های قبلی وجود دارد.

## محدودیت‌ها و رفتار خطا

- فقط پیام‌های جدید پس از شروع سرویس پایش می‌شوند؛ تاریخچهٔ قدیمی بازخوانی نمی‌شود.
- دسته‌بندی خبر/غیرخبر به مدل هوش مصنوعی واگذار شده است؛ فیلتر محافظه‌کارانه است، اما ممکن است گاهی یک پست را اشتباه دسته‌بندی کند. پست‌های مبهم رد می‌شوند.
- پست‌های رسانه‌ای بدون متن یا کپشن نادیده گرفته می‌شوند.
- در خطای Coarena یا انتشار تلگرام، پست به‌عنوان موفق علامت نمی‌خورد و خطا در لاگ ثبت می‌شود؛ پست خودکار دوباره امتحان نمی‌شود مگر رویداد تازه‌ای برسد.
- متن ورودی برای خلاصه‌سازی به Coarena فرستاده می‌شود؛ مطابق مستندات سرویس، درخواست و پاسخ ذخیره می‌شوند.
