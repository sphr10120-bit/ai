# ربات خلاصه‌ساز اخبار بازی برای Railway

این Worker هر ۱۰ دقیقه خوراک RSS سه سایت Zoomg، Gamefa و Vigiato را بررسی می‌کند. فقط مطلب‌هایی که در RSS به‌طور مشخص در دستهٔ اخبار بازی هستند وارد مرحلهٔ بررسی می‌شوند؛ سپس مدل دقیق `gpt-6-luna` در Coarena آن‌ها را از نظر خبری‌بودن ارزیابی می‌کند و خبرهای واقعی را به فارسی خلاصه می‌کند. خلاصه فوراً از طریق Bot API در `@pixelmediair` منتشر می‌شود. این نسخه نیازی به `api_id`، `api_hash` یا نشست حساب شخصی ندارد.

## منابع و فیلتر

- Zoomg: `https://www.zoomg.ir/feed/`
- Gamefa: `https://gamefa.com/feed/`
- Vigiato: `https://vigiato.net/feed/`

فیلتر RSS فقط دسته‌هایی را قبول می‌کند که صریحاً «اخبار بازی» باشند. مطالب سینما، نقد، بررسی، راهنما، آموزش، سرگرمی، تبلیغ و دسته‌های نامشخص حذف می‌شوند. مدل هم یک بار دیگر خبر بودن را می‌سنجد و اگر تردید داشته باشد، مطلب را منتشر نمی‌کند. دریافت RSS هر ۶۰۰ ثانیه انجام می‌شود؛ می‌توان این فاصله را با `POLL_INTERVAL_SECONDS` تغییر داد.

## قالب انتشار

- تیتر برجسته با پیشوند `🟦`، حداکثر دو خط.
- دو بند عادی، هرکدام حداکثر سه خط.
- یک خط فاصله و سپس `🆔 @pixelmediair` به‌صورت برجسته.
- لینک مقاله در متن خروجی درج نمی‌شود.

## ساخت ربات تلگرام و دسترسی مقصد

1. در تلگرام به `@BotFather` پیام بده و با دستور `/newbot` ربات بساز.
2. توکن Bot API را دریافت کن. توکن را در چت یا مخزن GitHub نفرست.
3. ربات را به کانال `@pixelmediair` اضافه کن و ادمینش کن؛ مجوز ارسال پیام لازم است.
4. توکن را در Railway به‌عنوان متغیر محرمانهٔ `BOT_TOKEN` تنظیم کن. کد در شروع فقط با `getMe` اعتبار توکن را بررسی می‌کند و پیام آزمایشی در کانال نمی‌فرستد.

## Coarena

یک کلید شخصی Coarena با scope `inference:write` بساز، شرایط Model API را بپذیر و کلید را در Railway به‌عنوان `COARENA_API_KEY` تنظیم کن. API در `https://coarena.ai/api/v1` فراخوانی می‌شود و شناسهٔ مدل دقیقاً `gpt-6-luna` است؛ در صورت ناموجود بودن مدل، مدل دیگری خودکار انتخاب نمی‌شود.

توجه: طبق مستندات Coarena، درخواست و پاسخ API ذخیره می‌شوند و ممکن است در مجموعه‌داده‌هایی که سرویس مجوز می‌دهد استفاده شوند. متن مقاله‌های ورودی برای خلاصه‌سازی به Coarena ارسال می‌شود.

## استقرار روی Railway

1. مخزن `sphr10120-bit/ai` را در Railway به‌عنوان GitHub Service متصل کن. این پروژه باید به‌شکل Worker دائمی اجرا شود؛ دستور شروع در `Procfile` و `railway.toml` تعریف شده است.
2. در بخش **Variables** سرویس، این متغیرها را اضافه کن:
   - `BOT_TOKEN` — توکن BotFather، محرمانه.
   - `COARENA_API_KEY` — کلید Coarena، محرمانه.
   - `DESTINATION_CHANNEL=@pixelmediair`
   - `DATABASE_PATH=/app/data/processed.sqlite3`
   - `POLL_INTERVAL_SECONDS=600`
   - `LOG_LEVEL=INFO`
3. در Railway یک Volume بساز و آن را به مسیر `/app/data` متصل کن تا پایگاه SQLite و سابقهٔ مقاله‌های پردازش‌شده با restart از بین نرود.
4. برای اعمال تغییرات متغیرها، **Deploy** را بزن. بعد از push تغییرات جدید به GitHub، Railway معمولاً سرویس متصل را دوباره build/deploy می‌کند؛ اگر خودکارسازی خاموش باشد، آخرین commit را از بخش Deployments دستی Deploy کن.
5. در Deploy Logs باید پیام `Telegram bot authenticated as ...` و سپس تعداد RSS feeds را ببینی. اولین اجرای موفق، آیتم‌های فعلی RSS را فقط به‌عنوان baseline ذخیره می‌کند تا یک‌باره خبرهای قدیمی را در کانال منتشر نکند. از اجرای بعدی، خبرهای جدید را بررسی می‌کند.

متغیرهای قدیمی `TELEGRAM_API_ID`، `TELEGRAM_API_HASH` و `TELEGRAM_SESSION` در نسخهٔ جدید لازم نیستند؛ می‌توانی آن‌ها را از Railway حذف کنی. توکن BotFather را در GitHub یا چت قرار نده.

## خطاهای رایج

- اگر لاگ `BOT_TOKEN was rejected` نشان داد، توکن را در BotFather بازنشانی کن و مقدار جدید را در Railway جایگزین کن.
- اگر تلگرام `chat not found` یا `not enough rights` داد، مطمئن شو ربات در کانال مقصد ادمین است و مجوز ارسال پیام دارد.
- اگر Coarena مدل را نپذیرد، خطا ثبت می‌شود؛ ربات مدل دیگری را جایگزین نمی‌کند.
- فیلتر RSS و فیلتر هوش مصنوعی محافظه‌کار هستند، اما دسته‌بندی سایت یا مدل می‌تواند اشتباه کند. مطالب بدون دستهٔ صریح اخبار بازی رد می‌شوند.
- فقط آیتم‌هایی که RSS سایت ارائه می‌کند قابل دریافت‌اند؛ اگر سایتی RSS را تغییر دهد یا موقتاً در دسترس نباشد، خطا در لاگ ثبت شده و دور بعد دوباره تلاش می‌شود.
